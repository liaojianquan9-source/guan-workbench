# 多片段落定帧工作流

## 预检

1. 展开并验证所有参考视频、目标区间或用户指定静帧。
2. 记录每个片段的画布尺寸、帧率、镜头边界和已有版本。
3. 按剪辑手法或镜头段分组，而不是只按文件名分组。
4. 每个组只选择一个落定帧。不同镜头即使排版相似，也分别建立来源记录。
5. 检查当前 Remotion 项目和已有组件；相同构图只新增案例 props，不复制整个渲染器。

## 每个片段

1. 查看入场结束到退场开始之间的画面，选择信息最完整的单帧。
2. 记录源文件、镜头区间、落定时间码和帧号。
3. 分析元素、组、百分比边界、锚点、层级、裁切和可替换内容。
4. 在 Remotion 中实现一个默认即为落定状态的可编辑组件。
5. 为下一次会变化的内容建立 props/schema；避免为只出现一次的实现细节建立通用抽象。
6. 渲染单帧并与原帧对照，只修复已经观察到的偏差。

## 无人值守容错

仅当用户明确要求无人值守或“遇到问题先跳过继续”时启用：

1. 单个片段读取或渲染失败不得中断整批。
2. 可恢复的读取、构建或渲染错误自动重试一次；仍失败则记录片段、阶段和错误摘要。
3. 找不到可信落定帧时不编造布局；标记为“待人工选帧”并继续。
4. 批次结束后列出成功、跳过和待复核的片段，不把跳过项计入完成数。

## 复核清单

- 每个镜头是否只选择了一个有来源记录的落定帧；
- Remotion 组件画布是否继承原视频；
- 主体位置、比例、裁切、对齐和层级是否接近原帧；
- 每个需要替换或后续独立运动的对象是否是可编辑元素；
- 共同运动的内容是否建立了合理分组；
- 文字替换后是否溢出或改变视觉中心；
- 是否误用整帧截图掩盖可拆分元素；
- 是否生成了黑白灰结构图或新的风格参考图片；
- 是否越界开始猜测入场、出场、转场或特效。

## 保存与汇总

- 组件建议命名为 `<case-id>-settled-layout-v<N>.tsx`，版本修订不静默覆盖。
- 来源记录与组件使用同一 `case-id`，保存目标区间和落定帧位置。
- 单帧验收图属于临时验证产物；除非用户明确要求，不把它加入案例资产。
- 批次完成后列出每个片段对应的组件、落定时间码和可替换内容。
