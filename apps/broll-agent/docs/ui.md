# AI工作台 · UI 决策与验证

## 第一轮：入口与批量审看

**依据。** 原工作台的拉片能力真实可用；复刻页是占位审查，AI 制作是规则匹配与浏览器草稿。新产品必须把持久制作项目、共享资产以及实际工具执行放在同一个可操作流程中，不能把旧占位图作为新结果。

**比较。** 纯聊天入口易于下指令，但不利于同时比较、修改几十张卡片；旧三栏工作台适合逐帧拉片，承载全项目制作会把研究记录与实例混在一起；采用项目页、批量卡片、按需展开依据与弹窗字段编辑，保留真实源视频、工具结果和所有卡片决定。

**实施。** 原生 HTML/CSS/JS，不新增前端运行依赖。浅色编辑台使用窄导航、大内容区域、固定批量操作栏；移动屏幕把导航放到上方。所有项目、资产和结果都从 4183 API 获取，初始空白库不会填充演示项目。

- 制作项目：新建纯文稿、带时码 JSON 或源视频项目；从原工作台导入；本地转写；运行、停止、恢复 Agent；展开事件与输入输出。
- 另建副本：从当前项目建立独立制作项目，复用固定版本的共享资产引用。原项目保持不变。
- 草稿审看：按待审/通过/保留口播/缺口/舍弃筛选；全选当前筛选；批量替换、实际预览、批准、舍弃和重置；单卡编辑使用相同接口。
- 替换：由样式字段合同生成编辑器；图片固定到资产 ID 和 revision；仅发送实际改动字段，保留每张卡片的其他内容。高级 JSON 仅在展开时出现。
- 结果：完成的渲染显示实际 `job.result.delivery.url`；重开项目后从 `project.deliveries` 继续播放、下载历史成片；项目导出与整个共享资产库导出分别提供。
- 参考研究：上传或选择源视频，播放器当前时间设置范围，保存研究笔记与实际抽帧；详情显示来源、证据和关联复刻任务。未完成复刻保持待处理状态。
- Skill 复刻：研究记录可调用 `POST /api/replicas` 建立复刻项目；详情按真实阶段状态展示范围预检、布局、动效、实现、验收。点击“继续下一阶段”调用 `advance` 的 `auto`，轮询实际 job，阶段失败保留错误与证据。不会因为按钮点击就前移阶段。
- 共享资产：图片/视频多选或拖放导入，各文件结果独立；浏览样式真实 poster 与原始/替换视频，查看来源许可与技术/保真状态；导入已知真实案例。

**取舍。** 第一轮不制作新的非编时间轴；精确字幕依赖已有转写或导入。纯文稿时间明确标为估算，不在 UI 中伪造精确时码。现有原拉片工具作为独立链接继续使用。元数据、工具结果和高级字段保留在可展开区域，默认界面聚焦口播、画面与决策理由。

## 验证标准

`node --test tests/test_ui.cjs` 覆盖真实时码校验、版本化批量请求、只提交当前项目选中卡、图片版本引用、上传部分失败继续、源视频空稿建项目、文本注入与外链阻断。虚拟 DOM 边界测试实际加载 `app.js`，模拟 API 返回后点击控件，检查拒绝、预览、真实成片 URL 和 Agent 失败恢复；不会将测试数据放进产品。

静态脚本使用 `node --check public/app.js` 与 `node --check public/logic.js` 校验。主 Agent 集成后执行真实浏览器、真实素材与实际模型/渲染验收；在该验收完成前，本文件不声称真实产品端到端通过。

**命名修正。** 产品名称严格使用“AI工作台”，不加空格、不添加别名；页面标题、桌面侧栏和移动入口均使用这一名称。“共享资产库”仅作为功能区名称，原拉片工具链接保留原功能名称。命名约束已加入 UI 回归测试。
