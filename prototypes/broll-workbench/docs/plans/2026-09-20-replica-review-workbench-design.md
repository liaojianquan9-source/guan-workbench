# 复刻审批工作台设计

## 目的

把复刻 Skill 的阶段门与人工确认过程放进现有拉片工作台。用户先从全局看一批连续片段，再逐片段、逐场景静态帧审查，不让单张图片的比较遮住整批任务的进度。

## 信息结构

「复刻」是单一工作台，不存在总览页与详情页之间的跳转。左侧每个片段是一张完整任务卡：左列是原视频片段缩略图，中列是来自 `layout.scenes[]` 的可变数量落定静态帧，右列是该片段静态布局门的汇总状态。中间始终显示当前静态帧的原片、复刻与对比工具；右侧始终显示当前静态帧的证据、意见和批准动作。点击任务或静态帧只更新同页内容。

## 审批门禁

每个 `sceneId` 静态帧有「待审查、需修改、已通过、生成中」状态。要求修改必须填写针对该帧的意见；「需修改」必须先重新生成，回到「待审查」后才能批准。一个片段的所有静态帧均通过后，才解锁该片段的动效分析；动效连续性通过后才进入完整特效实现与渲染。

当前实现是交互样例：使用工作台内已导入视频的真实缩略图演示可变数量场景、逐帧审批与布局门；复刻图暂用同一缩略图占位，不代表已生成或已比较。演示分组并非 Skill 的场景划分，批准仅影响浏览器内的演示状态。正式接入时，静态帧直接读取 Skill 产出的 `sourceStill`、`renderStill`、`comparisonStill`、`status` 和 `observation`。

## 对比视图

默认只显示准备批准的复刻静态帧，减少持续分屏造成的画面压缩。需要核对时可切换：复刻、原片、左右、叠加、划像、差异。叠加提供透明度，划像提供分界位置，左右适合构图核对，差异用于快速发现变化区域。

## 后续接入

生成服务接入后，任务卡应读取真实案例、`layout.scenes[]` 和三类 still 证据；动效阶段读取 `motion.motions[]` 与 `motion.continuity`，最终阶段读取完整渲染和 QA 门。评论和批准写入对应 `sceneId` 的持久化记录。目前原型审批状态仅保存在浏览器本机存储中。
