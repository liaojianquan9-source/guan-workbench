# 拉片工作台：界面与流程理解

> **⚠️ 历史记录：I/O 已于 2026-09-19 下线、仅作当时留档。**

日期：2026-09-18。范围：为后续重新设计建立产品理解；本次没有修改界面、播放器或素材数据。不是完整的可用性验收或 Impeccable critique 命令报告。

## 产品目的与研究单位

核心任务是从参考视频中找到值得研究的连续内容，看清画面变化、听清声音关系，保存观察，并能回到来源复查。

三个对象需要清楚区分：

- 原视频：完整来源，包含全片镜头、字幕与原片时间。
- 镜头：自动检测得到的切分结果，帮助定位；不等于完整的研究案例。
- 研究片段：用户圈定的连续范围，可以跨镜头，收纳多张关键画面、声音结果和时间点笔记；范围内字幕来自原片。

当前片段保存的是来源与范围，不自动导出新 MP4。三轨共用来源时间和范围，尚不支持单轨独立移动、裁剪或拼接。背景声包含音乐与音效，不能表述为纯音乐轨。

## 当前任务路径

导入视频 → 查看全片、镜头或字幕 → I/O 圈定范围 → 保存并命名片段 → 逐帧看画面、分轨回听、记录笔记 → 返回来源或寻找下一段。

研究内部是反复查看和记录的循环，不是必须顺次完成的向导：看一帧、回听一句、记观察、再次回看可以自由交替。

资料整理与输出是后续用途。全片分镜表、字幕导出已有入口；片段 MP4、片段级字幕和分镜表导出不能视为已完成能力。

## 已经成立的基础

统一播放器、三条对齐音轨和一根播放线，符合画面与声音对应研究的任务。方向键逐帧、I/O 选区、关键画面来源定位、片段范围与笔记关联都值得保留。

轨道头采用类型图标、锁、眼睛、静音、S 是已有明确偏好。后续不能为了减少图标而退回成大段说明和文字试听按钮。需要通过状态、悬停提示、键盘焦点和一致行为解释控件。

## Skill 的适用边界

- Emil design engineering：用于高频操作、反馈、状态切换和动效取舍。逐帧、定位和键盘操作应立即响应；面板过渡不能阻塞操作。
- Impeccable：适用 Operate 模式，强调任务、层级、一致性和熟悉的专业工具控件。本次只参考产品界面原则；没有启动正式 critique 双评估流程。context 启动脚本因执行权限失败，直接读取项目资料；未找到工作台内的 PRODUCT.md 或 DESIGN.md。
- UI UX Pro Max：后续补齐组件状态、键盘路径、焦点、对比度，以及空、加载、失败状态。
- Taste Skill：其说明明确排除多步骤产品界面，不作为本工作台的主导规则。
- shadcn：工作台目前是 HTML/CSS/JavaScript，未发现 components.json；不因安装 Skill 而迁移技术栈。
- Design MD：在确定品牌参考或设计令牌需求后使用。品牌官网的视觉资料不能直接替代专业工具的操作布局。

## 后续设计应回答的问题

1. 用户当前在浏览整条视频，还是研究已保存片段，能否一眼判断？
2. 能否同时看清视频、时间线和当前笔记，避免资料遮挡画面？
3. 每一次截图、笔记和回听是否明确属于当前片段，并可追溯到原片？
4. 保存片段后下一步是否自然，研究结束后是否容易找到下一段？
5. 分离中、没有字幕、没有人声、读取失败时，是否仍能继续其余研究工作？
