# [产品名待定] B-roll 再创作工作台 PRD

> 文档代号：B-roll Workbench  
> 版本：v0.1  
> 状态：产品定义稿，可用于 GPT-6 继续设计与开发  
> 日期：2026-09-08  
> 首期形态：本地优先、单人使用的桌面工作台  
> 核心原则：AI 可以提出、生成和检查；只有用户批准的分镜与素材，才能进入最终时间线。

## 0. 一页结论

这个产品不应被定义成“素材处理工具”“模板素材库”“分镜表”或“一键生成视频工具”。它应该被定义成：

> 一个面向口播视频的、分镜驱动的 B-roll 再创作工作台。它把口播内容转成可解释的视觉决策，从经过验收的模板中匹配表达方式，让用户无代码完成改字、换图、素材统一、预览、回填时间线和导出，并把每次完成的镜头继续沉淀为可复用知识。

产品由两条流程组成：

1. 日常制作工作台：处理“这一期视频哪里需要 B-roll、用什么、怎么改、如何放回去”。
2. 模板工厂：处理“看到一个好镜头后，如何把它复刻成合法、可编辑、可验证、可重复使用的模板”。

两条流程共用模板库、素材库、风格规范、渲染能力、QA 体系和来源记录，但必须保持独立。模板工厂不替代分镜判断，制作工作台也不在首版内承担任意视频的全自动复刻。

产品最重要的数据对象不是 MP4，而是“可执行分镜卡”：

> 对应台词与时间范围 + 是否需要 B-roll + 叙事目的 + 模板版本 + 可替换内容 + 素材处理 + 风格参数 + 渲染状态 + QA 结果 + 人工决定

建议采用“方案 B：分镜驱动的再创作工作台”，把“模板素材库”作为其中一个模块，把“一键全自动成片”留到真实数据证明判断可靠之后。

## 1. 背景与现状

### 1.1 已经拥有的能力

当前工作区并非从零开始，已经具备：

- 一套连续 B-roll 复刻流程，可完成范围预检、静态布局、动效取证、Remotion 实现与保真 QA。
- 两个真实案例、七条 SHOT 的候选素材库，以及原片、复刻、替换效果证据。
- 一个 B-roll 素材库网页原型，可浏览案例、用途、标签、预览和替换字段。
- 一条真实口播的字幕、编辑判断、时间线 JSON、完整合成视频与人工审阅记录。
- Remotion 确定性渲染、FFmpeg 媒体处理和逐镜头 QA 能力。

这些资产证明“模板能够被生产出来”，但还没有证明普通用户能在不进入代码的情况下，把模板用于一条新的真实口播。

### 1.2 参考项目的正确位置

| 参考项目 | 可借鉴内容 | 不应承担的职责 | 集成策略 |
|---|---|---|---|
| [codex-storyboard](https://github.com/Yuuhann1999/codex-storyboard) | 分镜卡、A/B-roll 表达、生成器选择、任务队列、本地媒体、Remotion 等生成出口 | 不作为项目数据真源；不负责“是否需要 B-roll”的决策；不替代时间线与知识库 | 借鉴交互和任务编排，必要时做适配层 |
| [Material Stylizer](https://github.com/sakuraoxo-clio/material-stylizer-web) | 批量导入、抠图、描边、阴影、半调、网格、波点、渐变、折痕、PNG 导出 | 不负责分镜判断、模板匹配、时间线或成片；不能把普通 Canvas 放大称为 AI 超分 | 首期作为独立工具或洁净重写处理能力，不直接合并其源码 |
| 现有 Replica Skills | 把指定参考片生产为可编辑、可验收的 Remotion 案例包 | 不分析新口播，不决定插入点 | 作为后台“模板工厂” |
| 现有 B-roll 素材库 | 浏览和展示真实案例、样式、替换字段与证据 | 不直接保存项目级镜头实例，不替代数据库 | 迁移成 Template Registry 的种子数据 |
| Remotion | 可编辑模板的确定性预览和渲染 | 不负责内容判断、素材权利和产品状态 | 作为渲染执行层 |

### 1.3 当前断点

现有能力之间缺少一条稳定的转换链：

| 环节 | 用户真正要解决的问题 | 当前断点 |
|---|---|---|
| 叙事判断 | 哪句话需要画面，哪句话应该保留真人，为什么 | 素材库不知道何时使用；生成工具容易过度插入 |
| 视觉匹配 | 这句话适合哪种构图、动效和表达任务 | 分镜表可以排信息，却不了解模板适用语义 |
| 内容替换 | 如何把参考镜头换成自己的文字、图片、数据 | 一次性生成不可编辑；工程模板要求用户懂代码 |
| 风格统一 | 杂乱素材如何成为同一条视频的一部分 | 素材工具只处理文件，不理解镜头和项目风格 |
| 时间线落地 | 结果如何准确覆盖回口播，并保留原音频 | 语义决策与剪辑时间线分离 |
| 复用沉淀 | 这次做完后，下次能否更快 | 普通成片只留下像素，没有留下结构化经验 |

## 2. 第一性原理

### 2.1 根问题

用户缺少的不是“更多 B-roll”，而是一条低成本、可控制、可复用的转换链：

> 把口播中需要被看见的内容，转换成与叙事匹配、可修改、风格统一，并能准确回到时间线中的画面。

因此，系统的输入不是一句生成提示词，而是：

- 用户自己的口播与表达意图；
- 口播的准确时间关系；
- 已被验证的视觉语法；
- 用户自己的文字、图片、数据和品牌规范；
- 人对叙事和取舍的最终判断。

系统的输出也不只是一个视频文件，而是：

- 一份每段都做过决定的分镜；
- 一组可继续修改的镜头实例；
- 一条可以重建的时间线；
- 一份可验证、可追溯的导出结果；
- 一批能继续被检索和复用的数据。

### 2.2 七个价值假设

1. 决策比生成更有价值。最困难的部分首先是“哪里需要什么画面”，不是按下生成按钮。
2. 可编辑模板比一次性生成结果更适合高频创作。固定布局和动效、替换内容，才能同时得到速度、稳定性和一致性。
3. AI 适合提出建议，人必须掌握最终叙事权。错误 B-roll 会破坏真实感、节奏和情绪。
4. 用户口播决定新视频讲什么，参考视频只贡献视觉语法，不控制新视频叙事。
5. 模板生产与模板使用是两条不同流程。Replica 是后台模板工厂，工作台是日常制作界面。
6. 长期资产不是 MP4 数量，而是结构化镜头知识：何时适用、为何适用、能改什么、如何渲染、何时被接受或拒绝。
7. 风格统一必须发生在完整镜头语境内。抠图、描边和调色是镜头制作步骤，不是脱离项目的终点。

### 2.3 不可违背的产品原则

1. 叙事优先于素材。不能因为库里有漂亮模板，就强行插入。
2. “不需要 B-roll”是一等编辑结果，必须与“需要”同样被保存。
3. 所有 AI 建议必须显示对应台词、时间段、用途、理由和置信度。
4. 所有决定都必须可覆盖、撤销、锁定和回溯。
5. 可替换性优先于一次性的视觉惊艳。
6. 分镜数据是项目事实源，文档、预览和 MP4 都是派生产物。
7. 同一参数的预览与正式导出必须尽量一致。
8. 参考素材与用户素材必须分离，默认排除平台标识、原字幕、署名和品牌元素。
9. 模板、素材、字体、纹理、模型输出必须保留来源和许可记录。
10. 模型、生成器和供应商必须可替换，项目数据不能锁死在 GPT-6 或某个服务中。
11. 质量优先于覆盖率，少而准确优于把整条视频填满。
12. 先证明“选择—替换—预览—插回—导出”闭环，再扩展平台。

## 3. 用户、场景与任务

### 3.1 核心用户

第一阶段服务高频制作知识类、产品类、教程类口播的个人创作者和小型内容团队。他们会写内容、懂基本剪辑，但没有时间或动效工程能力重复制作高质量 B-roll。

### 3.2 核心 JTBD

> 当我已经有一条口播视频或字幕稿时，我希望快速判断哪些内容值得用画面解释，并从经过验证的模板中生成可修改、风格一致的 B-roll，准确放回口播时间线，让我把时间花在内容和最终判断上，而不是反复搭动画。

次级任务：

- 看到喜欢的参考镜头时，把它拆成合法、可编辑、可验证的视觉模板，供未来项目复用。
- 推荐模板不完全合适时，直接修改文字、图片、数据、颜色和时间，不进入代码工程。
- 素材来源杂乱时，在镜头上下文内完成抠图、描边、阴影和色彩统一。
- 成片效果不理想时，知道问题来自选点、模板、素材、时间还是渲染。

### 3.3 首版不服务

- 需要完整专业非编能力的影视后期团队；
- 只想一句提示词直接生成整片且不参与确认的用户；
- 以复杂三维、角色动画或电影级视效为主的用户；
- 首期就需要多人实时协作、云资产权限和公开模板市场的组织客户。

## 4. 产品定位与边界

### 4.1 产品定义

| 维度 | 定义 |
|---|---|
| 产品类别 | 口播视频 B-roll 再创作与编排工作台 |
| 核心价值 | 把叙事判断、模板复用、内容替换、素材统一、准确回填和验收连成闭环 |
| 核心对象 | 可执行分镜卡 Storyboard Shot |
| 主要交互 | AI 提案 + 人工确认 + 无代码编辑 + 确定性预览 |
| 核心资产 | 结构化模板、适用语义、替换槽位、成功数据与 QA 证据 |
| 首期交付 | 本地可审阅成片、独立 B-roll、项目 JSON、时间线和来源清单 |
| 长期护城河 | “什么内容在什么语境下适合什么视觉语法”的真实使用知识 |

### 4.2 三种方案

| 方案 | 优点 | 根本风险 | 决策 |
|---|---|---|---|
| A. 全自动 AI 成片器 | 演示冲击强，步骤少 | 判断不可控、难修改、风格漂移、成本高 | 暂不采用；真实数据证明后再做自动模式 |
| B. 分镜驱动的共创工作台 | 同时解决判断、复用和落地，适配现有资产 | 需要统一数据结构和清晰交互 | 采用 |
| C. 模板素材库与导出工具 | 最快落地，能复用现有七条 SHOT | 没解决“哪里该用什么”的核心难题 | 作为 B 的一个模块 |

### 4.3 首版范围内

- 导入口播视频、音频、SRT 或文稿；
- 保留和校正原始时间码；
- 以语义段落判断需要、可选或不需要 B-roll；
- 输出用途、理由、置信度和建议时长；
- 从已验收模板中给出主选和备选；
- 在分镜卡中接受、拒绝、换模板和调整时间；
- 替换文字、图片、数字和有限样式变量；
- 对替换素材进行基础统一处理；
- 单镜预览、区间预览与确定性渲染；
- 将已确认镜头覆盖回 A-roll，默认保留口播原音；
- 导出审阅成片、独立镜头、项目数据和来源清单；
- 录入已经通过 Replica 与 QA 的模板包。

### 4.4 首版范围外

- 任意参考视频的端到端全自动复刻；
- 替代 Premiere、Final Cut、CapCut 等完整剪辑软件；
- 自动重写整篇口播或完成复杂 A-roll 精剪；
- 无人工确认的一键终版成片；
- 任意生成式视频的无限参数编辑；
- 云端多人实时协作、账户权限和审批；
- 模板市场、公开社区、支付体系；
- 移动端制作和云端批量渲染；
- 自动解决版权、肖像、商标和授权问题。

## 5. 产品结构与核心流程

### 5.1 双入口工作台

    首页
    ├── 制作新视频
    │   └── 导入 → 分析 → 选点 → 匹配 → 替换 → 预览 → 时间线 → QA → 导出
    └── 添加新样式
        └── 参考片 → 范围锁定 → 布局 → 动效 → Remotion → 复用测试 → QA → 发布
                         │
                         └────────── 共用模板与镜头知识库 ──────────┘

MVP 只需要让“制作新视频”形成完整闭环。“添加新样式”先继续调用现有 Replica 流程，到 P1 再进入同一 UI。

### 5.2 日常制作流程

1. 新建项目，确定画幅、帧率、语言和输出规格。
2. 导入口播与已有字幕；没有字幕时转录并对齐。
3. 用户确认内容简报：主题、受众、目标、语气、品牌。
4. 系统切分叙事节拍，识别每段的作用和关键信息。
5. Planner 为每段提出“需要 / 可选 / 不需要 B-roll”，并解释原因。
6. 对需要或可选段落，系统检索模板并生成可执行视觉简报。
7. 用户逐卡接受、拒绝、改时间或换候选；锁定的决定不被重算覆盖。
8. 系统实例化模板，把关键词、图片、数字预映射到槽位。
9. 用户无代码改字、换图、裁切、处理素材并套用项目风格。
10. 用户查看单镜、相邻镜头和完整区间预览。
11. 只有通过人工确认的镜头进入 B-roll 轨道。
12. 系统运行技术、内容、风格和权利 QA，导出结果与可恢复项目。

### 5.3 模板工厂流程

1. 导入参考片并记录来源、权利状态。
2. 锁定连续范围、包含项与排除项。
3. 拆场景、转场和稳定元素 ID。
4. 取证布局、层级、遮挡和安全区。
5. 取证入场、内部运动、退场与连续镜头关系。
6. 落地成数据驱动的 Remotion 模板。
7. 定义替换槽位、约束、适用语义和不适用情形。
8. 使用至少两套差异明显的新内容做复用测试。
9. 通过静帧、连续运动、完整渲染、来源与替换 QA。
10. 发布不可变的 TemplateVersion，供制作工作台检索。

### 5.4 人工检查点

| 检查点 | AI 可以做 | 必须由人决定 |
|---|---|---|
| 分镜选点 | 分析、提出三态建议、解释和估计置信度 | 接受、拒绝、修改时间 |
| 模板匹配 | 检索、排序、说明匹配与风险 | 最终选择模板或不用模板 |
| 内容替换 | 预填文字、建议素材、生成处理配方 | 确认事实、品牌、肖像和最终画面 |
| 模板发布 | 运行布局、动效、替换与许可检查 | 批准模板进入正式库 |
| 终版导出 | 运行完整性和技术 QA | 豁免风险并批准终版 |
| 外部服务 | 列出拟上传内容和用途 | 明确同意上传 |

## 6. 信息架构与界面

### 6.1 一级页面

| 页面 | 目的 | 核心内容 |
|---|---|---|
| 首页 | 创建和继续工作 | 制作新视频、添加新样式、最近项目、失败任务 |
| 项目工作台 | 完成一条口播的 B-roll 闭环 | 播放器、分镜、检查器、时间线、任务状态 |
| 模板库 | 检索和理解可复用视觉语法 | 用途筛选、动态预览、适用范围、替换槽、QA、许可 |
| 模板工厂 | 把参考片变成可发布模板 | 范围、场景、布局、动效、替换、QA 阶段 |
| 素材库 | 管理原素材和派生版本 | 来源、处理配方、使用镜头、权利状态 |
| 渲染与 QA | 查看后台任务和阻塞 | 队列、失败原因、证据、重试、报告 |
| 设置 | 管理本地环境和外部能力 | 模型、渲染器、存储、字体、隐私、授权 |

### 6.2 项目工作台默认布局

- 左侧：字幕与叙事段落，可筛选“待确认 / 需要 / 可选 / 不需要”。
- 中央：A-roll 与当前 B-roll 的组合预览，可切换原片、模板、替换、成片。
- 右侧：当前分镜的理由、候选模板、替换字段、素材处理和样式。
- 底部：受控时间线与渲染队列；默认轨道为 V2 字幕图形、V1 B-roll、V0 A-roll、A0 口播原音。
- 顶部：项目进度、未解决阻塞、撤销、快照、预览和导出。

工作台不是完整 NLE。它只提供“口播 + B-roll 覆盖 + 字幕/图形”所需的时间线能力。

## 7. 数据模型与唯一真源

### 7.1 核心领域对象

| 对象 | 作用 | 核心字段 |
|---|---|---|
| Project | 一期视频的工作容器 | ID、标题、画幅、FPS、语言、状态、当前修订、风格 ID |
| MediaAsset | 不可原位覆盖的媒体源 | ID、SHA-256、类型、尺寸、时长、FPS、来源、许可、存储位置 |
| TranscriptRevision | 原稿与修订稿版本 | 来源、语言、版本、对齐状态、人工修订 |
| TranscriptSegment / Word | 时间对齐的文本单位 | startUs、endUs、文本、置信度 |
| NarrativeBeat | 可独立理解的叙事节拍 | 词区间、叙事作用、重要度、实体、视觉化潜力 |
| BrollDecision | AI 提案与人工结论 | yes/no/maybe、理由、建议范围、置信度、审批状态 |
| Template | 稳定的模板身份 | 名称、用途、标签、生命周期 |
| TemplateVersion | 不可变模板版本 | 案例包、版本、画幅、时长、槽位、QA、许可、已知差异 |
| ShotInstance | 项目中真正使用的镜头 | beat、模板版本、props、素材绑定、时间、人工状态 |
| AssetRecipe | 素材非破坏性处理 | 原素材、步骤、参数、处理器版本、派生素材 |
| StyleProfile | 项目级视觉约束 | 字体、颜色、圆角、阴影、安全区、效果强度 |
| TimelineTrack / Segment | 已批准镜头的实际位置 | 轨道、帧范围、素材引用、层级、音频策略 |
| RenderJob / Manifest | 可恢复、可复现的渲染 | 输入快照哈希、状态、进度、错误、输出 |
| QAReview | 门禁与证据 | 类型、结果、观察、责任对象、豁免、人工签字 |
| ProvenanceRecord | 来源和使用边界 | 来源、作者、许可、授权证明、限制 |
| AgentRun | AI 行为审计 | 模型、提示版本、输入快照、输出、成本、采用结果 |

### 7.2 每个领域只有一处可编辑真源

- SQLite：项目、节拍、镜头实例、人工批准、任务状态和模板目录索引的事务真源。
- 内容寻址媒体仓库：图片、视频、音频的二进制真源，以 SHA-256 标识，禁止原位覆盖。
- Replica 案例包：模板母版真源，保留 case、layout、motion、Remotion、evidence 和 validation 合同。
- DESIGN.md 或 StyleProfile：项目级视觉约束；镜头显式覆盖项优先。
- timeline.json、分镜 Markdown、预览图和 MP4：全部是可重建、带版本号的派生产物，不得反向静默覆盖项目数据。
- 已批准版本不可直接改写；任何修改产生新 Revision，可比较和回滚。
- 现有七条 SHOT 应迁移为 TemplateVersion，不能继续把前端 data.ts 当数据库。

### 7.3 时间与轨道规则

- 原始媒体时间保存为整数微秒 startUs / endUs。
- 渲染使用 startFrame / endFrameExclusive，并记录 FPS 分子与分母。
- 不用浮点秒作为最终剪辑真源。
- Source Time 与 Edited Time 必须分离；A-roll 改剪后通过 EditMap 映射。
- A-roll 原音轨默认是音频主轨；B-roll 默认只覆盖视觉。
- 修改字幕文本不能静默改变原始时间码。
- 分镜卡和时间线必须双向编辑同一 ShotInstance，不能各自保存一套。

### 7.4 模板包最低合同

每个可发布模板必须提供：

- templateId、语义版本、来源 case 和包哈希；
- Composition 入口与兼容的 Remotion 版本；
- 场景、帧范围和稳定 elementId；
- 可替换参数的类型、默认值、必填项、长度或位数限制和适配方式；
- 图片槽的比例、最小尺寸、裁切策略、安全区和抠图要求；
- 适用叙事、推荐时长和不适用情形；
- 默认预览、替换预览和完整转场预览；
- 布局、动效、连续性与替换冒烟 QA；
- 来源、许可、品牌限制和已知差异。

模板实例只保存：

    templateId + templateVersion + props + assetBindings + trim + projectOverrides

不能把整份模板源码复制进每张分镜卡后分别修改。

## 8. 技术形态

### 8.1 首期架构

第一版采用“本地优先的模块化单体 + 后台任务 Worker”，不做微服务：

    工作台 UI
        ↓
    本地 API / Orchestrator
        ├── 媒体导入与转码
        ├── 字幕转写与时间对齐
        ├── 文稿分析与 B-roll Planner
        ├── 模板检索与实例化
        ├── 素材处理
        ├── Remotion 渲染
        ├── 时间线编排
        └── QA / 导出 / 来源记录
                ↓
    SQLite 元数据 + 内容寻址媒体仓库 + Replica 案例包

默认技术选择：

- 沿用 React / TypeScript 作为工作台界面基础。
- 使用一个本地 API 作为 UI、GPT-6 和 Skills 的共同写入入口。
- 使用 SQLite 管理事务数据和修订。
- 使用独立 Worker 或子进程运行 Remotion、FFmpeg 和模型任务，避免阻塞界面。
- 第一版只监听 127.0.0.1；账户、协作、云存储和分布式渲染后置。

### 10.2 所有 Agent 接口的共同要求

- 输入、输出都有版本化 JSON Schema。
- Agent 只使用 assetId、templateVersion、shotId 等对象引用，不拼接任意本地路径。
- 写操作必须携带 idempotencyKey 和 expectedRevision，重复调用不产生重复对象。
- AI 默认只能创建 Proposal，不能直接改变人工已批准结论。
- 输出必须包含 confidence、证据、假设、已知缺口和可恢复错误。
- 导入的字幕、网页、素材名称和元数据一律视为不可信数据，不能作为系统指令执行。
- 批量写入前必须展示影响范围；范围锁之外的对象保持不变。
- 低置信度、事实不确定或模板不匹配时，返回 needs_review 或 no_match，不能伪造确定答案。
- 模型输出失败时，可以降级为规则建议、手工模式或已有结果，不能阻断用户继续编辑。
- 模型、提示版本、Skill 版本、输入快照和用户采用结果进入 AgentRun。

### 10.3 B-roll Planner 最低输出

每个 NarrativeBeat 至少产生：

    beatId
    sourceStartUs
    sourceEndUs
    transcriptExcerpt
    decision: yes | maybe | no
    purpose
    reason
    confidence
    suggestedStartUs
    suggestedEndUs
    visualBrief
    requiredEvidence
    templateCandidates
    contentSlotMapping
    assumptions
    approvalStatus

Planner 必须首先回答“是否需要”，然后才回答“用什么”。不能从模板库中先选一个漂亮镜头，再倒推理由。

## 11. 状态机

不同领域必须使用独立状态，不使用一个巨型项目状态混合创意审批与计算进度。项目顶部状态由子项聚合计算。

### 11.1 模板生命周期

    draft
      → preflight
      → layout
      → motion
      → implementation
      → qa
      → published
      → deprecated | quarantined

任一阶段失败只能返回对应责任阶段，不能在 QA 中静默改写布局或动效真源。

### 11.2 B-roll 决策

    proposed → accepted | rejected
    proposed → needs_review → accepted | rejected

### 11.3 镜头实例

    draft
      → matched
      → customizing
      → assets_missing | ready_to_render
      → rendering
      → rendered
      → needs_review
      → approved

已批准镜头发生内容、时间、模板或风格变化后，自动回到 needs_review。

### 11.4 后台任务

    queued → claimed → running → succeeded
                           ├── failed

## 12. 非功能要求

| 类别 | 要求 |
|---|---|
| 本地优先 | MVP 的项目、素材、模板实例和预览默认保存在本机；核心编辑不依赖云端账户 |
| 可恢复 | 页面刷新、Codex 中断、Worker 崩溃或应用重启后，可从最近检查点继续 |
| 确定性 | 同一 TemplateVersion、props、素材哈希、渲染器版本和规格应得到相同结果 |
| 帧精度 | 最终插入点误差不超过一帧；所有时间换算有自动测试 |
| 非破坏性 | 原媒体、原字幕和已批准版本不可原位覆盖 |
| 可解释 | 所有 AI 选点、匹配和阻塞都有用户可理解的理由 |
| 性能反馈 | 普通编辑操作 300ms 内给出界面反馈；后台任务空闲时 2 秒内开始或说明原因 |
| 预览目标 | 基准开发机上，4–8 秒 720p 试点镜头的草稿预览中位时间不超过 15 秒 |
| 稳定性 | 合法输入的单镜渲染成功率目标不低于 95%；单镜失败不拖垮整片 |
| 自动保存 | 重要编辑在 2 秒内持久化，并支持撤销、快照和恢复 |
| 可移植 | 导出的项目包包含数据合同、模板版本引用、资产清单和重链接机制 |
| 无障碍 | 状态不只依赖颜色；关键审核流程支持键盘操作和清楚的文本标签 |
| 可观测 | Job 有进度、阶段、错误码、日志引用、产物引用和建议动作 |
| 模型可替换 | 业务对象与 GPT-6、具体图像模型或生成器解耦 |
| 向后兼容 | Schema 升级提供迁移；旧项目和旧模板不能因前端升级而不可打开 |

## 13. 错误、安全与许可

### 13.1 统一错误合同

错误对象至少包含：

    code
    stage
    message
    recoverable
    retryable
    jobId
    artifactRefs
    logRef
    suggestedActions

规则：

- 缺素材、缺许可或缺人工决定是 blocked，不是 failed。
- 模型置信度不足是 needs_review，不得自动猜测。
- 网络和临时资源错误可退避重试；参数、字体、源码错误不盲目重复。
- 媒体写入使用临时产物后原子完成，源媒体永不原位覆盖。
- Worker 使用租约和心跳；超时任务可重新领取。
- 乐观锁冲突必须阻止后写覆盖先写。
- 删除默认进入项目回收站；已发布模板、已批准时间线和来源记录不能级联硬删。
- 输入文件哈希变化后，下游对齐、预览、渲染和 QA 自动失效并提示重做。

### 13.2 隐私与安全

- 默认只绑定本机地址；不在局域网或公网暴露未鉴权接口。
- 提供完全本地模式，关闭云模型、遥测、外部字体和素材请求。
- 调用第三方 AI 前，展示将上传的具体文本、图片或视频及用途。
- 对 MIME、尺寸、时长和解压体积做实检；媒体解析放在低权限进程。
- 规范化路径并限制可访问目录，防止路径穿越、SSRF 和任意文件访问。
- 日志不保存密钥、完整私人文稿和不必要的绝对路径。
- 字幕、网页、文件名和素材元数据可能包含提示注入，只作为数据解析。
- 参考片默认私有使用，不自动发布、出售或分享。

### 13.3 许可隔离

- codex-storyboard 当前仓库采用 MIT，可作为交互与编排参考；集成前仍需保留其许可声明并重新核验最新版本。
- Material Stylizer 当前仓库采用 AGPL-3.0，品牌素材与部分第三方纹理有单独边界。闭源产品首选独立外部工具或洁净重写，不直接复制其源码；若修改或部署其代码，先完成正式许可评估。
- Material Stylizer 的 2 倍、4 倍 Canvas 重采样不得在本产品中标记为 AI 超分。
- Remotion 用于商业产品或自动化渲染前，应依据届时官方条款重新确认许可证与费用。
- 模板、字体、图片、音乐、参考视频和模型生成物分别建立 ProvenanceRecord。“代码可用”不等于“其中素材可商用”。
- 权利检查只能管理证据和风险，不能替用户提供法律保证。本节不是法律意见。

## 14. MVP：严格截止线

### 14.1 MVP 要证明的唯一命题

> 不懂 Remotion 的用户，能否利用一个真实模板，在一条真实口播中完成“自动选点—人工确认—换字换图—预览—插回—导出”，并且明显快于当前手工流程。

任何不能直接帮助证明这个命题的功能，不得阻塞 MVP。

### 14.2 MVP 基线

- 单个本地用户，不做账户和云协作。
- 一条 2–5 分钟的真实口播视频与校准 SRT。
- 试点规格优先采用现有案例兼容的 16:9、30fps；数据合同必须能表达其他画幅和帧率。
- 现有两个案例和七条 SHOT 先以“候选模板”迁移，不宣称全部已经参数化或通过产品级验收。
- 只选择一条真正可换字、换图、稳定渲染的模板作为垂直切片，优先 SHOT-003。
- 真实黄金样本使用 2026-09-07 口播项目；首个选点可采用 02:45.100–02:53.733 附近的“更换本期文案与图片”段落。
- 输出审阅 MP4、独立 B-roll、项目 JSON、分镜表、RenderManifest、QAReport 和来源清单。

### 14.3 MVP 必须跑通

1. 新建项目并导入口播、SRT、图片素材。
2. 媒体探测通过，原始文件哈希和时间基准入库。
3. 将字幕合并为语义段，并为每段生成需要、可选或不需要的建议。
4. 每条建议显示时间、台词、理由、用途和置信度。
5. 用户能接受、拒绝、修改时间并锁定结果。
6. 对一个接受的选点推荐 SHOT-003，并说明为什么匹配。
7. 将本期文案和至少一张新图片映射到模板槽位。
8. 用户不修改源码即可改字、换图、调整裁切和查看草稿预览。
9. 生成正式单镜 B-roll，并按批准时间插回 A-roll。
10. 保留 A-roll 原音频，检查前后节奏和一帧级时间位置。
11. 通过占位符、文字边界、黑帧、素材来源和媒体规格检查。
12. 导出完整审阅视频和可重新打开的项目。
13. 修改一项内容后只重渲染受影响镜头。
14. 应用重启后仍能恢复项目、批准状态和任务结果。

### 14.4 MVP 不做

- 工作台内的任意视频全自动复刻；
- 一次处理整套七种样式并承诺全部可商用；
- 根据一句提示词自动批准整片；
- 完整 NLE、多轨音频混音和复杂 A-roll 精剪；
- 多人协作、云渲染、模板市场；
- Premiere、Final Cut、CapCut 的双向工程同步；
- 生成式视频的高级编辑；
- 批量内容生产和多平台发布。

### 14.5 MVP 验收标准

| 维度 | 通过标准 |
|---|---|
| 无代码闭环 | 用户不打开 Remotion 源码即可完成导入到导出 |
| 分镜完整 | 每个语义段都有明确三态结论，没有未解释空白 |
| 可解释 | 试点推荐包含原台词、用途、理由、置信度和候选模板 |
| 人工控制 | 未批准镜头不能进入正式时间线；锁定决定不被重算覆盖 |
| 内容替换 | 至少文字和图片两类内容真正变化，且不是预制假数据 |
| 复用保真 | 替换后模板构图、主要动效和连续关系保持，原品牌与字幕不残留 |
| 文字安全 | 无截断、溢出、不可读字号和安全区冲突 |
| 媒体技术 | 输出可完整解码，无黑帧、空帧，分辨率、FPS、总帧数符合预设 |
| 时间准确 | 插入点与批准帧范围误差不超过一帧 |
| 音频连续 | A-roll 原音频未被意外替换、截断或漂移 |
| 可恢复 | 重启后项目可打开，素材引用、状态、快照和成片可追踪 |
| 可追溯 | 输出能追溯模板版本、素材哈希、处理配方、模型与 QA |
| 首次价值 | 基准机从导入到第一个可用 B-roll 的中位时间不超过 15 分钟 |
| 稳定性 | 有效输入的单镜渲染成功率达到 95% 目标 |

## 15. 验证计划与指标

### 15.1 北极星指标

真实项目闭环成片率：

    完成导入 → 分镜确认 → 内容替换 → 预览 → 导出的真实项目数
    ÷
    启动制作的真实项目数

它衡量用户是否完成工作，不以生成次数、模板总数或页面停留时间代替。

### 15.2 早期验证门槛

MVP 跑通后，连续使用不少于 5 条真实口播验证：

- 至少 4/5 个项目无需进入代码即可完成闭环；
- 推荐镜头至少 60% 被接受或轻微调整后采用；
- 已确认制作的镜头至少 80% 进入最终审阅成片；
- 单镜合法输入渲染成功率不低于 95%；
- 导入到首个可用 B-roll 的中位时长不超过 15 分钟；
- 2–5 分钟视频的 B-roll 流程相较人工基线节省至少 50% 时间；
- 用户能说明每个镜头为何出现，不出现明显“为了有画面而有画面”；
- 换字换图后，构图、动效和可读性通过人工检查。

停止扩张条件：

- 推荐接受率持续低于 40%；或
- 修正 AI 分镜所需时间接近手工规划；或
- 模板实例多数仍需修改源码；或
- 预览与最终导出的偏差持续让用户重新返工。

命中任一条件时，应优先修复判断、模板合同或预览一致性，不扩展生成器和模板数量。

### 15.3 配套指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 效率 | 导入到首个可用镜头时间 | 首次价值速度 |
| 效率 | 单条视频完整 B-roll 制作时长 | 与现有人工基线对比 |
| 判断质量 | 推荐接受率 | 直接接受或轻改后采用 |
| 成片质量 | 最终保留率 | 已生成镜头最终留在成片的比例 |
| 叙事质量 | 过度插入率 | 人工认为不该出现 B-roll 的推荐比例 |
| 模板价值 | 模板复用率 | 新项目中复用已验收模板的比例 |
| 可编辑性 | 无代码完成率 | 未进入源码完成替换与导出的项目比例 |
| 稳定性 | 预览和渲染成功率 | 合法输入成功并可重现的比例 |
| 返工成本 | 单镜平均修改轮次 | 区分选点、素材、模板和渲染问题 |
| 资产成长 | 已通过 QA 的模板数 | 不统计只有预览但不可替换的样式 |
| 知识成长 | 建议采用与拒绝原因覆盖率 | 推荐系统是否获得真实反馈 |

## 17. 主要风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 范围无限扩大 | 同时讨论 NLE、市场、云协作和一键生成 | 只用 MVP 唯一命题决定首期工作 |
| AI 选点不可靠 | 接受率低、用户大量删除 B-roll | 强制三态、理由、置信度和人工批准；记录拒绝原因 |
| 过度插入 | 真人情绪和节奏被持续覆盖 | 将 no-B-roll 设为一等结果并做密度检查 |
| 模板供给不足 | 多数选点都返回 no_match | 先聚焦知识、产品、教程表达；将缺口转成模板工厂任务 |
| 假复用 | 换文字图片后频繁溢出或改源码 | 发布前双内容测试，TemplateVersion 声明约束和已知差异 |
| 时间码漂移 | 字幕正确但镜头插错位置 | 微秒与帧双时间基准、EditMap、边界测试和一帧验收 |
| 风格拼贴感 | 单镜好看但整片不统一 | StyleProfile、语义令牌、素材 Recipe 和全片 QA |
| 工具链脆弱 | 一个渲染失败导致整项目停摆 | Worker、检查点、镜头隔离、可重试错误和缓存 |
| 多份真源 | UI、JSON、Remotion props 相互覆盖 | 所有写入经过统一 API；派生产物只读可重建 |
| 模型锁定 | GPT 或生成器升级后旧项目不可重建 | 版本化 AgentRun、稳定 Schema 和可替换适配器 |
| 许可污染 | AGPL 源码或原视频品牌进入产品 | 独立进程或洁净重写；来源门禁；默认私有模板 |
| 用户期待完整剪辑软件 | 不断要求复杂音频与多轨精剪 | 界面和文案持续强调“受控 B-roll 覆盖时间线” |
| 隐私外传 | 未发布口播被静默上传 | 本地默认、逐能力同意、日志脱敏和本地模式 |
| 提示注入 | 字幕或网页内容诱导 Agent 执行动作 | 所有导入内容视为数据；Agent 只调用受控对象 API |
| 成功样本偏差 | 只在一个熟悉案例上可用 | 至少五个真实项目、不同主题和内容长度验证 |

## 19. 给 GPT-6 的实施说明

### 19.1 工作顺序

GPT-6 接手时不得从页面美化或重新生成演示数据开始。按以下顺序执行：

1. 阅读本 PRD 与第 20 章列出的真实资产。
2. 审计当前代码、案例包、时间线和数据结构，列出能复用与需要迁移的部分。
3. 固定 Project、MediaAsset、NarrativeBeat、BrollDecision、TemplateVersion、ShotInstance、RenderJob、QAReport 的版本化 Schema。
4. 明确每个领域的唯一真源、派生产物和迁移策略。
5. 把现有七条 SHOT 迁移为候选 TemplateVersion，不伪造 QA 通过状态。
6. 只选择 SHOT-003 建立真实可编辑垂直切片。
7. 实现导入真实口播和 SRT、生成三态提案、人工确认。
8. 实现模板匹配、换字换图、非破坏性素材处理和草稿预览。
9. 实现已批准镜头回填时间线、完整审阅视频和交付清单。
10. 加入状态恢复、错误合同、来源门禁和最小 QA。
11. 用真实 9 月 7 日项目完成端到端验收，保存证据。
12. MVP 通过后再扩展其余模板、模板工厂 UI 和智能推荐。

### 19.2 实现约束

- 不创建第二套项目 JSON 与数据库争夺真源。
- 不把 timeline.json、预览 MP4 或分镜 Markdown 当作可编辑业务数据库。
- 不让 UI、Skill 或 Agent 直接修改模板源码或任意本地文件。
- 不用演示卡片或静态假数据代替真实导入、真实模板实例和真实渲染。
- 不把现有七种样式全部标为“已通过”。
- 不因为 AI 给出建议而自动批准。
- 不上传媒体或全文而不显示范围和用途。
- 不复制 Material Stylizer 的 AGPL 源码进入可能闭源的核心。
- 不在 MVP 内建设微服务、账户体系、Marketplace 或完整 NLE。
- 任何缓存、文档和视频都必须能够从版本化真源重建。

### 19.3 每个开发阶段的完成定义

一个阶段只有同时满足以下条件才算完成：

- 功能通过对应 Schema 和状态机合同；
- 使用真实素材而非占位数据运行；
- 有正常路径、失败路径和恢复路径；
- 有自动化合同测试或时间基准测试；
- 有可视预览或机器可读产物作为证据；
- 不覆盖用户原素材和已批准版本；
- 变更记录说明实现了哪些功能 ID；
- 文档、实际行为和导出结果一致。

### 19.4 可直接交给 GPT-6 的首轮任务

> 以本 PRD 为产品真源，先不要扩展全部功能。审计当前工作区的真实案例、Remotion 模板、素材库原型、9 月 7 日口播时间线和 QA 文档，提出一份“P0 合同统一 + P1a 单镜闭环”的实施计划。计划必须说明唯一真源、数据迁移、目录边界、状态机、Agent API、测试、许可隔离和失败恢复。然后只实现 SHOT-003 的真实垂直切片：导入口播与 SRT，生成可解释的三态 B-roll 提案，经人工批准后完成换字换图、预览、按帧回填、QA 和导出。不得用静态假数据替代真实闭环，不得把七条 SHOT 全部宣称为已验收模板。

## 21. 最终产品判断

这件事确实可以做成一个产品，但产品价值不在“把三个开源项目拼起来”，而在于建立一个以前没有被统一表达的中间层：

> 从口播叙事到可执行视觉决策，再从可执行视觉决策到可复用、可修改、可验收的镜头。

如果首个真实闭环成立，素材库会从展示站变成供给层，Replica 会从单次复刻变成模板工厂，分镜台会从文档变成项目控制面，素材处理会从独立滤镜变成镜头制作步骤，而 GPT-6 会成为受约束的分析与编排者。

如果首个闭环不成立，继续增加模板、模型、页面和生成器只会把问题做大。因此，下一步不是继续扩充概念，而是用 SHOT-003 和真实口播完成一次可计时、可回放、可验收的垂直切片。
